1. WHAT IS CodeIT
================================================================================

CodeIT is a full-stack competitive programming / coding practice platform.

Tagline (landing): "Master Competitive Programming, Together."

Core loop:
  learn DSA  ->  practice problems (real judge)  ->  AI coach when stuck
  ->  Quick Clash with friends  ->  timed competitions  ->  collaborate in rooms

It is similar in spirit to LeetCode / HackerRank, with extra campus-friendly
capabilities: private friend battles (Quick Clash), realtime CodeRooms,
problem collaboration, and a Groq-backed AI learning coach.

Project status (as of docs):
  - Core coding, judging, submissions, competitions, profile: implemented
  - AI learning coach (Groq): implemented
  - Collaboration (CodeRoom + Problem Collab): implemented
  - Friends, notifications, Quick Clash: implemented
  - ADMIN Command Center (problem + competition studios): implemented
  - Primary UI: frontend-stitch/ (active migration)
  - Legacy UI: frontend/ (still available)

2. PRODUCT POSITIONING & AUDIENCES
================================================================================

2.1 Students / self-learners
  - Practice multi-language problems with real compile/run feedback
  - Follow DSA sheet lessons
  - Get gated AI hints instead of dumping full solutions
  - Clash with friends privately; join scheduled contests
  - Pair-program or whiteboard in CodeRooms

2.2 Faculty / trainers (workflow mapping)
  - Product roles today are USER and ADMIN only (no dedicated faculty role)
  - Faculty workflows map onto: ADMIN (author problems/contests) + room HOST
  - Use competitions as timed labs; CodeRooms for office hours
  - AI coach scales first-line "I'm stuck" questions

2.3 Colleges / institutes
  - One arena for placement prep + coding fest tracks
  - Live leaderboards and profiles as measurable activity
  - Reduces tool sprawl (OJ + Discord + Docs + judge)

2.4 Platform operators
  - ADMIN Command Center to author problems and schedule contests

3. HIGH-LEVEL ARCHITECTURE
================================================================================

  Browser (React)
       |  REST + JWT
       v
  Spring Boot API (port 9091)
       |-- PostgreSQL
       |-- Redis (OTP, rate limits, cache-aside)
       |-- Judge0 (code execution)
       |-- Groq LLM (AI coach)
       |-- STOMP/SockJS broker (/ws)  <--> Browser realtime events
       |
  Browser <--> Yjs sync-server (port 1234)  [editor + whiteboard CRDT]
       sync-server validates short-lived JWT sync tokens minted by the API

Flow summary:
  1. Register / login -> JWT
  2. Browse problems / languages
  3. RUN = sample/custom Judge0 execution (not saved)
  4. SUBMIT = all hidden tests, saved verdict
  5. Competition submits update live leaderboard over STOMP
  6. Rooms: Spring owns membership/chat/run/submit; Yjs owns shared docs
  7. Admins use /admin in Stitch UI

7.1 Authentication & account
  - Register: name, uniqueUserId, email, password (always role USER)
  - Email OTP verification (Redis + Brevo); login blocked until verified
  - Resend verification OTP
  - Login with email OR unique user ID
  - Forgot-password: request OTP -> verify -> reset
  - JWT token_version bumped on password reset (invalidates old sessions)
  - RSA-OAEP encryption of sensitive auth fields before POST
  - Optional Cloudflare Turnstile on auth/contact
  - BCrypt password hashing
  - Contact Us form (DB row + email to inbox)

7.2 Profile & progress
  - Own profile (/api/profile/me) and public profile by username
  - Edit bio, avatar, location, show_email, display name settings
  - Change password
  - Bookmarks (add/remove/list)
  - Recent problem views (track + list)
  - Submission history on profile
  - Contest history on profile
  - Stats: solved count, acceptance, difficulty breakdown, streaks,
    contest best rank, friend count (rating may be placeholder)

7.3 Problems & coding workspace
  - Browse / search / filter by difficulty / topic
  - Monaco editor with starter templates
  - Run against sample or custom stdin (not persisted as submission)
  - Submit against hidden tests (persisted)
  - Verdict, runtime, memory, passed cases, judge engine name
  - Hidden tests stripped from public problem payloads
  - Admin create problem (statement, examples, constraints, tests, topics)

7.4 Submissions history
  - List by user
  - List by problem
  - submission_diagnostics for richer failure metadata (AI analyze)

7.5 Scheduled competitions
  - Admin create contest (title, description, start/end, duration)
  - Assign ordered/set of problems
  - Global status: UPCOMING / ACTIVE / ENDED (from times)
  - Join; personal session JOINED / IN_PROGRESS / ENDED
  - Personal deadline = min(session start + duration, global end)
  - Contest submit
  - Live leaderboard: accepted count DESC, then runtime ASC
  - Patch contest times (ADMIN)
  - STOMP topics for leaderboard / status / session

7.6 Quick Clash (private friend contests)
  - Create lobby: name, difficulty tier EASY/MEDIUM/HARD,
    duration 15–120 min, max players 2–10
  - Auto-pick random problems by tier
  - Invite friends; join / ready / leave
  - Host start / cancel
  - LIVE solve + submit + leaderboard
  - History
  - States: LOBBY -> LIVE -> ENDED / CANCELLED
  - Designed NOT to affect global rating / profile solved stats
  - AI coach disabled during Quick Clash (product rule)
  - Notifications for invite / starting / ended

7.7 Friends
  - List friends
  - Search users by unique user ID
  - Send friend request
  - Respond accept / reject
  - Remove friend
  - Undirected friendship edges stored with user_id_low < user_id_high

7.8 Notifications inbox
  - List notifications
  - Unread count
  - Mark one read / mark all read
  - Types include: FRIEND_REQUEST, FRIEND_ACCEPTED,
    QUICK_CONTEST_INVITE, QUICK_CONTEST_STARTING, QUICK_CONTEST_ENDED
  - STOMP push via NotificationEventPublisher

7.9 Collaboration rooms
  Two room types:
    A) PROBLEM_COLLAB — bound to a problem; shared run + submit
    B) CODEROOM — freeform; shared run; whiteboard supported; no shared submit

  Shared capabilities:
    - Invite token join
    - Members with roles HOST / EDITOR / VIEWER
    - Transfer host, kick/change member role
    - Chat (rate-limited, max 2000 chars)
    - Presence / last_seen
    - Shared Monaco editor via Yjs (room:{id}:code)
    - Workspace switch CODE <-> WHITEBOARD (CodeRoom)
    - Host note (up to 280 chars)
    - Sync-token mint for sync-server
    - Leave / end room
    - Caps: max 10 members/room; whiteboard element/stroke limits

7.10 AI learning coach (Groq)
  Actions:
    - coach (general)

9. AUTHENTICATION & SECURITY
================================================================================

9.1 Session model
  - Stateless JWT after login
  - Claims include role and token_version
  - Password reset increments token_version -> old JWTs rejected

9.2 Email verification
  - OTP stored in Redis (pepper: CODEIT_OTP_PEPPER)
  - Without Redis: OTP flows fail closed (EMAIL_TEMPORARILY_UNAVAILABLE)

9.3 RSA-OAEP for sensitive fields
  - Frontend fetches GET /api/crypto/public-key
  - Encrypts login id / passwords before POST
  - Backend decrypts then bcrypt-verifies
  - Still requires HTTPS in production

9.4 Captcha
  - GET /api/captcha/config exposes whether enabled + site key
  - When CODEIT_CAPTCHA_ENABLED=true, Turnstile required on public spam surfaces

9.5 Rate limiting (defaults; see application.properties)
  Login:            5 / 15 min / IP
  Register:         limited per IP (see props)
  Forgot-password:  1 / day / email AND 1 / day / IP
  Run:              burst 3/10s, sustained 8/60s, daily 300
  Submit:           burst 2/10s, sustained 5/60s, daily 150
  AI:               burst 1/10s, sustained 5/60s, daily 40
  Room invite:      10 / 60s
  Room chat:        30 / 60s
  Room join:        10 / 60s
  Sync-token:       20 / 60s
  Transfer host:    3 / 60s
  Problems read:    90 / 60s / IP
  Admin write:      15 / 60s

9.6 STOMP auth
  - SockJS /ws handshake is public
  - STOMP CONNECT requires JWT (StompAuthChannelInterceptor)

10. JUDGING PIPELINE (Judge0)
================================================================================

Pipeline:
  SubmissionService
      -> TestCaseJudgeService
          -> CompileOnceJudgeService      (all langs except C#)
          -> ProgressiveBatchJudgeService (C#)
              -> Judge0Service

RUN  (POST /api/submissions/run)
  - One Judge0 submission with wait=true
  - Not saved to submissions table

SUBMIT (POST /api/submissions/submit)
  - Evaluates all hidden tests in problems.test_cases JSONB
  - Stores row in submissions (+ diagnostics when applicable)

Compile-once engine:
  - Uses Judge0 multi-file language ID 89
  - Compile once, run per input
  - Stop on terminal failure
  - Defaults: 3s per case; 30s CPU / 45s wall aggregate

Progressive batch (C#):
  - First batch 3 cases, then batches of 6
  - Stop after first failing batch
  - Poll every 200 ms; 60s timeout

Output comparison:
  - Trailing whitespace per line ignored; other differences matter

Programs must read stdin and write stdout.

17. COLLABORATION (YJS SYNC-SERVER)
================================================================================

Split of responsibility:
  Spring API  = room authority (members, roles, chat, run, submit, tokens)
  sync-server = CRDT sync for editor + whiteboard documents

Yjs document names (typical):
  room:{id}:code
  room:{id}:whiteboard

Client flow:
  1. Join room via API
  2. GET /api/rooms/{id}/sync-token
  3. Connect ws://localhost:1234 with token
  4. sync-server validates JWT (shared CODEIT_JWT_SECRET with API)

Caps (application.properties):
  max-members-per-room=10
  max-chat-message-chars=2000
  max-stomp-sessions-per-user-per-room=2
  max-whiteboard-elements=2000
  max-whiteboard-strokes=500
  max-stroke-points=400
  max-undo-steps=50

Start:
  cd sync-server && cp .env.example .env && npm ci && npm start
  or: docker compose up sync-server --build

21. LOCAL SETUP CHECKLIST
================================================================================

  Prerequisites:
    - JDK 21+
    - Node.js ^20.19 or >=22.12
    - PostgreSQL
    - Redis
    - Judge0 with multi-file language 89
    - GROQ_API_KEY if using AI

  Steps:
    1. createdb codeit; psql -f schema/schema.sql
    2. docker run -d --name codeit-redis -p 6379:6379 redis:7
    3. Export env vars (DB, JWT, Judge0, mail, Groq, captcha as needed)
    4. ./mvnw spring-boot:run          -> http://localhost:9091
    5. cd sync-server && npm ci && npm start  -> :1234
    6. cd frontend-stitch && npm ci && npm run dev  -> :5175
    7. Promote admin via SQL; open /admin

Promote admin:
  UPDATE users SET role = 'ADMIN' WHERE email = 'you@example.com';
  Then log in again for a JWT with ADMIN role.

23. KNOWN LIMITATIONS & ROADMAP

  - No automated E2E suite
  - Judge0 external / not version-pinned by this repo
  - Base schema still bootstrapped via schema/schema.sql;

  - Full cutover to frontend-stitch; retire legacy frontend
  - Full-stack Docker Compose (Postgres, Redis, Judge0, API, sync, UI)
  - Broader automated tests
  - Competition draft / update / publish APIs
  - Observability (structured logs, metrics)
